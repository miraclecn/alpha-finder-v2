# K线结构与趋势公共方法 v1（纯日线，道氏理论）

## 1. 目标与边界

本方法用于从纯日线历史数据中提取中等级别以上的结构信息，形成可复用的公共研究层，供后续策略调用。

它的职责是：

- 提取已确认的有效转折点
- 定义当前趋势状态
- 识别趋势反转与延续形态
- 计算关键支撑、压力与结构确认位
- 输出结构事实，供策略层组合使用

它不负责：

- 直接给出买卖建议
- 直接定义候选池或仓位
- 处理基本面、题材、事件与组合构建
- 代替交易可行性、风险预算与执行约束模块

核心原则：

- 全部计算仅使用历史已确认数据
- 严禁未来数据与事后回填结论
- 趋势是主状态，形态是趋势变化或延续的证据
- 公共层输出结构事实，不输出策略判断

## 2. 理论基础

本方法以道氏理论为基础。

- 上升趋势的核心特征是低点抬高，强确认可进一步要求高点抬高
- 下降趋势的核心特征是高点降低，强确认可进一步要求低点降低
- 形态是趋势过程中的结构表达，可用于识别整理、延续、衰竭与反转

本方法优先保留“结构可解释性”，不追求复杂机器学习式隐含判别。

## 3. 输入数据与时间定义

输入为按交易日升序排列的单只股票日线 DataFrame，字段为：

`date, open, high, low, close, volume, amount`

最低历史长度要求：

- 基础识别最低 `250` 个交易日
- 若用于大级别趋势判断，建议不少于 `500` 个交易日

统一时间口径：

- 所有跨度、窗口、级别全部按交易日计算
- 文档中不使用自然日或日历天

每个结构对象至少定义三个时间：

- `pivot_date`：实际拐点发生的交易日
- `confirm_date`：该拐点被确认、允许进入后续结构计算的交易日
- `signal_date`：某个趋势或形态对外生效的交易日

后续回测、扫描、选股只能使用当时已经到达 `confirm_date` 或 `signal_date` 的信息。

## 4. 有效转折点提取

### 4.1 原始局部极值

采用 `scipy.signal.argrelextrema` 识别局部极值：

- 波峰：`high` 序列在左右各 `order = 10` 范围内的局部最大值
- 波谷：`low` 序列在左右各 `order = 10` 范围内的局部最小值

输出原始转折点序列：

`raw_swings = [(pivot_date, pivot_price, type)]`

其中：

- `type = +1` 表示峰
- `type = -1` 表示谷

### 4.2 同类点压缩

原始极值合并后，不保证天然峰谷交替。必须先进行同类点压缩：

- 若连续出现两个峰，只保留价格更高的峰
- 若连续出现两个谷，只保留价格更低的谷

这样可避免同类连续点污染后续趋势与形态识别。

### 4.3 最小反转幅度过滤

从第一个候选转折点开始，顺序遍历压缩后的序列。

设上一个已接受转折点为 `last`，当前候选点为 `curr`，定义：

`change = abs(curr.price - last.price) / last.price`

当 `change >= MIN_MOVE_PCT` 时，`curr` 才保留为有效转折点。

默认：

- `MIN_MOVE_PCT = 0.05`

该阈值用于去除横盘噪声和微小波动。

### 4.4 峰谷交替化

在幅度过滤后，再次检查序列是否严格峰谷交替。

- 若仍存在连续同类点，继续按更极端者保留
- 最终序列必须满足峰谷严格交替

### 4.5 右侧确认

最后一个转折点不得自动视为可用。

确认原则：

- 局部极值本身已经隐含 `order` 根右侧观察窗口
- 在此基础上，最后一个有效峰谷仍视为“临时点”
- 只有满足后续结构破坏条件，才能转为“确认点”

建议确认规则：

- 最后一个峰，只有价格跌破其前一个确认谷后，才视为最终确认
- 最后一个谷，只有价格升破其前一个确认峰后，才视为最终确认

输出时，转折点应包含：

- `pivot_date`
- `confirm_date`
- `price`
- `type`
- `level`
- `confirmed`

## 5. 结构级别定义

级别依据同向转折点之间的交易日跨度划分。

- 小级别：`< 20` 日
- 中级别：`20 - 60` 日
- 大级别：`> 60` 日

说明：

- `250` 日以上可视为超大级别，但在 `v1` 中并入大级别
- 小级别不作为核心输出，只用于调试或辅助观察
- 当前公共层主输出中级别与大级别结构

## 6. 趋势定义与状态机

趋势是本方法的主状态。

### 6.1 上升趋势

候选上升趋势：

- 连续两个已确认波谷 `T1, T2`
- 满足 `T2.price > T1.price`

确认上升趋势：

- 在候选上升趋势成立后
- 价格再向上突破关键前峰

### 6.2 下降趋势

候选下降趋势：

- 连续两个已确认波峰 `P1, P2`
- 满足 `P2.price < P1.price`

确认下降趋势：

- 在候选下降趋势成立后
- 价格再向下跌破关键前谷

### 6.3 横盘与整理

当最新有效峰谷未形成明确的抬高低点或降低高点结构时，定义为：

- `range`

### 6.4 趋势状态

建议统一输出以下状态：

- `uptrend_candidate`
- `uptrend_confirmed`
- `downtrend_candidate`
- `downtrend_confirmed`
- `range`
- `reversal_attempt`
- `reversal_confirmed`

### 6.5 多级别趋势并存

同一时点允许不同级别趋势并存，例如：

- 大级别上升
- 中级别回调

因此输出至少区分：

- `big_trend`
- `mid_trend`
- `trend_stage`

## 7. 形态识别总框架

形态识别必须建立在“已确认有效转折点序列”之上。

形态分为三类：

- 反转形态
- 中继形态
- 结构事件类信号

每个形态统一输出以下信息：

- `pattern_type`
- `context_trend`
- `component_points`
- `geometry_complete`
- `breakout_confirmed`
- `volume_confirmed`
- `pattern_stage`
- `invalidated`

## 8. 反转形态定义

### 8.1 头肩底

前置趋势：

- 之前必须存在中级别下降趋势或下降中的整理结构

构成条件：

- 三个连续确认波谷 `L1, L2, L3`
- `L2.price < L1.price`
- `L2.price < L3.price`
- 左右肩价格近似
- 左肩到右肩的跨度达到最小交易日要求

关键位：

- 颈线定义为 `L1` 与 `L3` 之间的关键确认峰

状态建议：

- `forming`
- `geometry_complete`
- `neckline_breakout`
- `confirmed`
- `invalidated`

### 8.2 双底

前置趋势：

- 之前必须存在中级别下降趋势

构成条件：

- 两个相邻确认波谷 `L1, L2`
- 两底价格接近
- 中间反弹峰明显存在

关键位：

- 中间反弹峰作为突破确认位

状态建议：

- `forming`
- `geometry_complete`
- `breakout_confirmed`
- `confirmed`
- `invalidated`

### 8.3 预留形态

`v1` 可预留但不强制实现：

- 头肩顶
- 双顶
- 圆弧底

## 9. 中继与持续形态定义

### 9.1 上升三角形

适用背景：

- 上升途中整理
- 或下降后反转蓄势

构成条件：

- 至少两个确认波峰价格接近，形成水平压力
- 至少两个确认波谷逐步抬高
- 形态跨度达到最小交易日要求

状态建议：

- `forming`
- `geometry_complete`
- `breakout_confirmed`
- `confirmed`
- `invalidated`

### 9.2 突破前高

该对象更适合作为“结构事件”而不是完整形态。

定义：

- 当前收盘价突破最近一个中级别或大级别确认波峰

建议输出：

- 是否突破
- 是否站稳
- 是否放量
- 是否回踩成功

## 10. 关键位置计算

一级关键位优先：

- 最近中级别以上确认波谷
- 最近中级别以上确认波峰
- 当前形态颈线或平台线

二级关键位作为派生参考：

- 上升趋势线延伸值
- 下降趋势线延伸值
- 斐波那契回撤位
- 成交量密集区

当多个关键位冲突时，优先级为：

`确认峰谷 > 形态颈线/平台 > 趋势线 > Fib > 成交量密集区`

## 11. 量能与辅助确认

量能不是趋势主定义，只是辅助确认维度。

建议规则：

- 结构几何是否成立，只看峰谷关系
- 放量突破是否成立，单独输出
- 站稳确认是否成立，单独输出

量能字段优先级建议：

- 优先 `amount`
- 其次换手率
- 最后才是 `volume`

## 12. 输出接口设计

公共层只输出结构事实，不输出“应买应卖”。

建议单只股票输出结构：

```json
{
  "symbol": "600036.SH",
  "as_of_date": "2026-05-08",
  "big_trend": "uptrend_confirmed",
  "mid_trend": "reversal_attempt",
  "trend_stage": "mid_pullback_inside_big_uptrend",
  "confirmed_swings": [],
  "active_patterns": [],
  "key_supports": [],
  "key_resistances": [],
  "breakout_flags": {
    "above_last_mid_peak": false,
    "above_last_big_peak": false
  },
  "volume_confirmation_flags": {
    "breakout_amount_confirmed": false
  }
}
```

策略层再根据这些结构事实定义自己的筛选、打分和入场条件。

## 13. 参数与版本化

`v1` 保持简单、可解释、可复现。

主要可调参数包括：

- `order`
- `MIN_MOVE_PCT`
- 级别分界交易日
- 形态最小跨度
- 肩部、双底、平台线的价格偏差阈值
- 放量确认阈值

版本原则：

- `v1` 先建立统一结构定义
- 新增形态、分板参数、波动率缩放规则放到后续版本

## 15. 实现与验证要求

实现要求：

- 逐日回放验证，禁止整段事后识别后回填
- 所有结构对象必须保留确认时间
- 所有形态与趋势都要支持失效状态

验证要求：

- 横盘噪声样本
- 单日大幅波动样本
- 涨停/跌停样本
- 长停牌后复牌样本
- 新股上市初期样本
- 大级别趋势与中级别反向回调并存样本

性能要求：

- 支持全市场日级扫描
- 识别逻辑应保持顺序可解释与结果可复现

## 16. v1 结论

`v1` 的目标不是预测，而是统一“如何用日线结构描述趋势”。

它应首先成为：

- 一套可复现的趋势语言
- 一套可调用的结构输出接口
- 一套能够支撑后续策略研究的公共方法

在此基础上，策略层再决定：

- 哪些结构值得参与
- 在哪个形态阶段参与
- 如何结合流动性、基本面、风险约束与执行约束
